01背景

Ecommica 是一个面向海外多个国家和地区购物者的优惠信息站。访客可以按商家或分类（电子产品、家居园艺、时尚、工具、汽车、健康美妆、玩具、运动）浏览优惠、优惠券和折扣码，切换中英文和所在地区，也可以阅读博客内容。站内商家包括 Walmart US、Sam's Club US、Shopee MX 等。

这类站点的商业模式依赖联盟营销：用户从站内点出去、在商家完成购买，联盟网络回传转化。所以除了“内容要多、要新、能被搜到”，还有一条看不见但最关键的链路——每一次点击和转化都要记得准、对得上。

02我的角色 · 全栈

从前台页面到后端追踪服务、运营后台和部署，整条链路由我负责。

前台

Next.js 16 + React 19 + Tailwind 4；next-intl 中英双语路由、GeoIP 地区识别、ISR 缓存、sitemap 与 hreflang。

追踪与归因服务

Spring Boot 3.5 服务：点击记录与跳转、联盟 Postback 接收、去重与归因、联盟数据定时同步。

运营后台

Vue 3 + Element Plus + ECharts：商家、Offer、优惠券、文章管理，以及日统计报表与告警。

交付与质量

Docker Compose + nginx 部署；Playwright 端到端测试覆盖前台关键页面。

03关键挑战

C1 · 归因准确

点击和转化要一一对得上

联盟回传可能重复、延迟，也可能带着对不上的参数。重复计数会虚高收入，丢失又会少算，两种都不能接受。

C2 · 多语言多地区

同一个站，不同地区看到不同内容

中英双语路由、按地区筛选商家和优惠，同时要让搜索引擎正确理解每个语言版本。

C3 · 内容时效

优惠会过期，数据要持续更新

Offer 和优惠券来自外部联盟，需要定时同步，过期的要自动处理；页面既要快，又不能长期展示过期内容。

C4 · 好维护

少量人手也能长期运营

前台、服务、后台三套工程要结构清晰、部署简单、有自动化测试兜底，改动不容易把线上弄坏。

04方案与架构

下图基于源码梳理，只展示高层设计，与首页「架构与实现」一致。

  • 01 · 点击追踪

    站内出站链接统一走 /go/{类型}/{id}：记录点击与 sub1–sub5 参数后 302 跳转到联盟链接。

  • 02 · 转化归因

    联盟 Postback 支持签名校验，按外部转化号去重，再按点击 ID 关联生成转化；关联不上的单独留存待查。

  • 03 · 多语言多地区

    next-intl 中英双语路由，GeoIP 识别访客地区并按地区筛选内容；页面 ISR 缓存，输出 sitemap 与 hreflang。

  • 04 · 运营与数据

    联盟数据定时同步、优惠到期自动处理、日统计聚合与小时 / 日告警；运营后台基于 Vue 3 + Element Plus。

出站点击：统一入口，先记录再跳转

站内所有出站链接都走统一的跳转入口：服务端先记录点击（包括 sub1–sub5 追踪参数），再 302 跳转到联盟链接。这样每一次出站都有据可查，后续的转化才有可以关联的“锚点”。

转化回传：校验、去重、按点击归因

联盟网络的 Postback 先做签名校验，再按外部转化号去重，保证同一笔转化重复回传也只记一次；然后按点击 ID 关联到原始点击生成转化。关联不上的回传不丢弃，单独留存待查。计费模型支持 CPS / CPA / CPC / CPL / CPM，归因支持最后一次、首次和线性三种方式。

多语言、多地区与 SEO

前台基于 next-intl 做中英双语路由，GeoIP 识别访客地区并按地区筛选内容。商家、优惠和文章页使用 ISR 增量静态再生成，兼顾速度和新鲜度；同时输出 sitemap 和 hreflang，让搜索引擎正确索引各语言版本。

数据同步与运营

定时任务同步联盟网络的 Offer 和优惠券，到期优惠自动处理；统计模块按日聚合点击、转化等数据并提供小时 / 日级告警。运营人员在 Vue 3 后台管理商家、Offer、优惠券和文章，并查看报表。
