Case 04/Smart Community · IoT

润臻智慧大脑把社区、校园和多家厂商设备接到一个平台

一套同时服务社区物业和学校的管理平台：资产、住户与师生档案，收费与发票，报修、访客、考勤这些日常业务，再加上门禁、安防、停车和人脸设备的接入。我在河南润臻科技担任技术负责人。项目自 2022 年起分多期建设，第三期由我主导重构，整体架构、业务模块、厂商集成层和收费引擎由我编写。这页讲清楚它的难点在哪、我怎么设计。

01背景

润臻智慧大脑是一套社区 + 校园一体化的管理平台。同一套系统里，物业管理的是楼栋、单元、房屋、车位、车辆和水电表，学校管理的是年级、班级、教师和学生；两边共用同一套资产与人员模型，按租户隔离。

平台覆盖的业务大致分三层：

  • 日常业务：物业收费与数电发票、报修、投诉、访客、投票、场馆预约，校园考勤与请假、家长通知；
  • 设备与物联：人员和车辆通行、门禁权限、安防告警、停车、人脸识别、语音对讲、设备状态；
  • 看板：社区、学校、区域、年级、班级、教师、学生多个层级的统计看板，以及一块面向指挥中心的数据大屏。

难点不在某一个功能，而在设备来自多家厂商：每家的接口、实体、事件格式都不一样，业务代码却不能因此长出一堆 if-else。

02我的角色 · 技术负责人

在河南润臻科技担任技术负责人。项目自 2022 年起分多期建设，第三期由我主导重构：框架之上的业务模块由我设计并编写，第三期代码仓库约八成提交出自我手。

架构与模块划分

在开源后台框架之上新建业务模块，按资产、服务、收费、通行、考勤、看板等领域拆分；统一的状态机、定时任务和消息队列基础设施。

厂商集成层

把多家厂商的安防、门禁、停车、人脸平台收敛为同一套功能接口，负责启用配置、ID 映射、事件归一和联调用的 Mock Client。

收费与发票

费项、计费策略、折扣 / 赠送 / 减免、滞纳金、欠费通知、退款，以及数电发票的开具与红字确认。

多端协作

管理后台的业务页面，以及 uni-app 物业端、原生 App、H5、React 数据大屏和官网，共用同一套后端接口。

03关键挑战

C1 · 多厂商

同一件事，每家厂商一套接口

下发人员、授权门禁、查询通行，海康云眸、海康 C6000、大华 ICC、道尔停车、百度人脸，各家平台的接口、鉴权和实体 ID 都不一样；有的机构只开通了部分系统或部分功能。

C2 · 事件洪流

设备事件要实时、可扩展地处理

通行、告警、考勤事件从不同平台推送过来，格式各异；同一个事件可能要同时触发通行记录、考勤计算、告警和家长通知。

C3 · 收费规则

物业收费的组合非常多

周期性费用和一次性费用、预付和后付，叠加折扣、赠送、减免和滞纳金，还要发欠费通知、支持退款和数电发票。

C4 · 两类场景

社区和校园要用同一套底座

楼栋、房屋、车位和年级、班级、学生是两套语言，但人员、设备、通行和看板的逻辑高度重合，不能维护两套系统。

04方案与架构

下图基于源码梳理，只展示高层设计，与首页「架构与实现」一致。

统一集成层：业务只认功能，不认厂商

每一种设备能力（下发人员、门禁授权、查询通行、车辆进出等）都定义成一个功能动作。调用时先走统一的初始化：依次校验系统 → 功能 → 机构三级启用配置，确定这家机构用的是哪家平台，再由策略路由到对应厂商的 Client：目前接入的有海康云眸社区与云眸普教、海康 C6000、大华 ICC（视频预览与云台）、道尔停车（车辆与白名单、通道开闭）和百度人脸。本地的人员、房屋、设备与厂商侧实体的 ID 单独存一张映射，业务表不掺厂商字段。

这样新增一家厂商只需要实现一个 Client 和对应的映射，业务代码不动；集成层还带一个 Mock Client，没有真实设备也能把整条链路跑通联调。集成层本身约 2 万行代码。

事件管线：先归一，再分发

厂商推送的事件先进 Converter 工厂，按来源转换成统一的业务事件；再由 Handler 工厂按事件类型分发给通行、考勤、告警、请假、家长通知等处理器，一个事件可以同时被多个处理器消费。实体变更、事件、欠费、租户模块开通等消息走基于 Redis 的消息队列解耦，结果通过 WebSocket 推到管理后台和大屏；处理失败的事件和设备状态由定时任务补偿与同步。

收费策略引擎

费项按「周期 / 一次性」×「预付 / 后付」组合出四种计费策略，由策略工厂按费项选择，生成账单时叠加折扣、赠送、减免与滞纳金规则。欠费按费项生成通知，退款单独成单；发票对接数电发票，支持红字确认流程。

状态机与看板

报修、访客、请假、预约等带流程的业务共用一套状态上下文与状态处理器工厂，状态迁移集中在一处定义。看板按社区、区域、学校、年级、班级、教师、学生逐级聚合，大屏用 React 19 + ECharts 6 单独实现。

06交付情况

社区与校园共用一套底座

资产、人员、通行、设备、看板在两种场景下共用同一套模型和代码，按租户开通模块。

多家厂商接在同一套接口后面

海康、大华、道尔、百度的安防、门禁、停车、人脸平台统一走集成层；换厂商或加厂商只新增 Client，业务层不改。

设备事件实时到达各端

事件经归一、分发和消息队列处理后，实时推送到管理后台、移动端和数据大屏。

收费到发票的闭环

从费项、账单、优惠与滞纳金，到欠费通知、退款和数电发票，收费链路完整实现。

以上规模按第三期代码仓库统计（业务后端约 12 万行 Java、124 个接口控制器，管理端 245 个业务视图），描述的是工程规模，不代表用户量；运营数据这里不写。
