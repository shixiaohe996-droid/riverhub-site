用 AI 编程（Claude Code / SDD / TDD）做交付的实践

这两年我在真实项目里大量使用 Claude Code 这类 AI 编程代理，包括支付平台这种对正确性要求很高的系统。体会是：让 AI 写出代码很容易，让它写出能上线、能长期维护的代码，需要一整套工程方法托底。这篇记录我目前的做法。

我怎么分工：人定义问题，AI 写代码

我给自己的定位是“定义问题、制定规则、验收结果”，大部分具体编码交给 AI 代理：

  • 我负责：拆解需求、划定范围、写清验收标准；做架构决策；审查关键路径的改动；最终决定能不能合并。
  • AI 负责：按规格实现功能、补测试、修复验证中发现的问题、更新相关文档。

这个分工的前提是：AI 拿到的上下文必须足够清楚。所以下面几节其实都在回答同一个问题——怎么把“清楚”变成仓库里的东西，而不是停留在聊天记录里。

规格先行（SDD）

SDD（Spec-Driven Development，规格驱动开发）的核心是：先写规格，再写代码。每个功能开工前，我会在仓库里写一份 Markdown 规格，至少包含：

  • 背景和目标：为什么做，解决谁的什么问题；
  • 范围，以及明确不做什么——这一条对 AI 尤其重要，否则它很容易“顺手”改一堆不相关的东西；
  • 业务规则和边界情况：比如金额精度、并发、重复请求怎么处理；
  • 验收标准：可以直接翻译成测试用例的描述。

规格和工单都以文件的形式放在仓库里，跟代码一起评审、一起版本化。AI 开工时先读规格，交付时对照验收标准自查。半年后有人问“这里为什么这么做”，答案也在仓库里。

把决策写成规则

规格解决“这个功能做什么”，但还有一类知识是跨功能的：分层怎么划、跨域怎么保证一致、幂等怎么做、哪些写法禁止使用。这类知识我用两种方式沉淀：

  • 架构决策记录（ADR）：每个重要决策一份短文档，写清背景、可选方案、最终选择和代价。在支付平台项目里，这样的记录积累到了近百份。
  • 仓库级的代理规则文件：把最重要的约束、目录约定、常用命令和验证方式写成一份给 AI 读的说明。我同时使用多个 AI 编程工具，它们共用同一份规则，不用为每个工具各维护一套。

效果很直接：以前要在每次对话里反复强调的事，现在 AI 开工前自己就读到了；新加入的同事也是读同一套文档上手的。

测试先红后绿（TDD）

AI 写代码很快，但“看起来对”和“真的对”之间的差距，只能靠测试来量。我的要求是：

  1. 先根据验收标准写测试，跑一遍，确认它因为正确的原因失败（红）；
  2. 再写最少的实现让测试通过（绿）；
  3. 最后在测试保护下重构。

“先看到红”这一步不能省。AI 有时会写出永远通过的测试，或者为了让测试通过去改测试本身。先红后绿能把这类问题挡在外面。

对资金相关的代码，我会特别要求覆盖这几类场景：重复请求、并发冲突、外部调用超时、金额边界和精度、状态不能倒退。这些恰恰是 AI 最容易忽略、出了问题代价最大的地方。

验证门禁：不靠自觉

规则写得再好，如果没有自动检查，迟早会被绕过——不管是人还是 AI。所以我会把验证做成门禁：

  • 用 Git 钩子在提交前跑格式化、静态检查和相关测试，不通过就提交不了；
  • 给每类改动定义“完成”的标准：编译、测试、构建都通过，才算这个任务结束；
  • 准备演示数据和端到端的业务旅程验证，从用户视角确认主要流程能走通，而不只是单元测试是绿的。

门禁的意义在于：AI 交付的东西，不需要我逐行信任，而是由机器先过一遍硬标准，我把注意力集中在设计和业务逻辑上。

并行：一个任务一个工作区

AI 代理的一个优势是可以并行。我会用 Git worktree 给每个任务开一个独立的工作目录和分支，几个代理同时推进互不相关的任务，彼此不会踩到对方的改动。每个任务完成、通过门禁后，再单独评审合并。

并行的前提是任务拆得足够独立、边界清楚，这又回到了规格先行。

AI 常犯的错，和我的应对

常见问题表现应对
范围蔓延顺手重构、改了不相关的文件规格写明“不做什么”；评审时先看改动范围
绕过约束为了跑通，跳过校验或吞掉异常规则文件明确禁止；门禁检查；关键路径人工审查
虚构接口调用不存在的方法或配置项编译和测试门禁；要求先读现有代码再动手
测试放水断言太弱，或改测试迁就实现先红后绿；测试和实现分开评审
上下文遗忘长任务后期忘了前面的约定任务拆小；约定写进规格和规则文件，而不是只在对话里说

几点建议

  • 先把工程基础打好再上 AI：没有测试和规范的项目，AI 只会更快地制造混乱。
  • 让知识进仓库：规格、决策、规则都写成文件，人和 AI 读同一份。
  • 验证自动化：能让机器检查的，就不要靠人盯。
  • 关键路径人来把关：资金、权限、数据一致性相关的改动，我一定自己看。
